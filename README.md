# 笔记问答机器人

拿自己的 Python 学习笔记当语料：问一句话，它从笔记里找出最相关的几段，连同问题一起发给大模型，
让模型**只根据这几段**回答。

两种用法，用的是同一套代码：

- **命令行** —— `python 主程序.py "闭包是什么"`
- **浏览器** —— 起一个服务，打开网页打字点「问」（`web\` 那部分）

```
 问题
  │
  ├─► 切块.py     把 28 篇笔记切成 587 个块（可用 454 块）
  │
  ├─► 检索.py     给每个块打分，挑出分数最高的 3 块
  │
  ├─► 主程序.py   把 3 块的正文和问题拼成一段提示词
  │
  └─► 问模型.py   发给 DeepSeek，拿到答案
        │
        ├─► 主程序.py 打印到终端                      （命令行）
        │
        └─► web/服务.py 包成 HTTP 接口 → 网页显示      （浏览器）
```

**一句话原理：模型没读过我的笔记。** 它回答时能看到的，只有这一次请求里发给它的那些字。
所以第 2 步「挑得准不准」，直接决定第 4 步「答得好不好」。

## 怎么跑

依赖都写在这一个文件里：

```powershell
pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
```

> 加 `-i` 那串是走阿里云镜像 —— 国内直连 PyPI 慢到卡死，清华镜像又缺包。

Key 从环境变量读，不写进代码：

```powershell
setx DEEPSEEK_API_KEY "你的 Key"
```

> `setx` 只对**之后新开的**终端生效 —— 它改的是注册表，不是当前这个窗口。

两种跑法，都在 `问答机器人\` 目录下：

```powershell
python 主程序.py "闭包是什么"     # 命令行模式：问完这一个就退出
python 主程序.py                  # 交互模式：一直问，空回车退出
```

问句里有空格**要加引号**。命令行是按空格切词的，不引起来会被拆成几个词再拼回去，空格会被抹平。

## 网页版怎么跑

依赖同上（`fastapi` / `uvicorn` 已经在 `requirements.txt` 里了）。

在 `web\` 目录下起服务：

```powershell
cd web
python -m uvicorn 服务:app --reload
```

然后浏览器打开 <http://127.0.0.1:8000>，就是一个输入框加一个「问」按钮。

`--reload` 让改完 `.py` 自动重启（改 `页面.html` 不用重启，浏览器 `Ctrl+F5` 刷新就行）。

顺带白捡一个接口文档：<http://127.0.0.1:8000/docs>，FastAPI 自动生成的，能在网页上直接发请求试。

## 五个文件各管一件事

| 文件 | 干什么 |
|---|---|
| `切块.py` | 把一篇笔记切成块：每块 = 一个标题 + 它下面的正文。靠一个 `在代码块里` 的开关跳过 ``` 里的假标题 |
| `检索.py` | 给每个块打分，返回分数最高的 3 块。只读，不写任何东西 |
| `问模型.py` | 发一次请求、把答案掏出来。外面套一层重试：网络抽风就重试，Key 错了直接认输 |
| `主程序.py` | 把上面三步串成一条线，管命令行 / 交互两种入口 |
| `web\服务.py` | 把那三步包成 HTTP 接口（`POST /问`），外加一个网页 |

## 检索怎么打分的

`检索.py` 自己不算分，它转手给 `检索_向量.py`：

1. **变成向量** —— 问题和每一块都交给硅基流动的 `BAAI/bge-m3`，各变成一串数字。
   意思越近，这串数字的方向越像。
2. **比夹角** —— 问题向量和每块向量算余弦相似度：1 = 方向一样，0 = 没关系。
3. **取前三** —— 按夹角从大到小排，拿前 3 块交给模型。

为什么不拆词了：老办法把「闭包是什么」切成 `闭包` `包是` `是什` `什么`，
`包是` 这种跨词碎片本身没意义，但因为它罕见反而权重最高，能把真答案挤出前三。
向量看的是意思，没有"碎片"这回事。

而且在选块之前还先筛了一道（`不是垃圾块()`）：正文短于 50 字**且不含反引号**的块扔掉，
标题是 `## 进度` 的台账块不参加排名。前者因为短而完整的答案常常只有二三十字
（比如「先 `.isdigit()` 再转」），一刀切会误伤；标注代码的短块一律留下。

向量只需要算一次：算过的存进 `_向量缓存.json`，之后直接读回来（这个文件不进仓库）。

## 网页那边在干什么

页面只有三件事：把问题发出去、看牌子、把答案贴上来。

```
浏览器                     服务端
  │                          │
  │  POST /问                │
  │  {"问题": "闭包是什么"}   │   ← 只有这一栏，Key 不在这
  │ ────────────────────────►│
  │                          │  主程序.回答一个问题(...)
  │                          │   └─ 问模型.py 自己去环境变量里拿 Key
  │  {"答案": "..."}          │
  │ ◄────────────────────────│
```

**Key 只存在服务端的环境变量里，前端永远碰不到它。** 页面能发的只有一个问题。

出事了，门口那块牌子（HTTP 状态码）分两种：

| 谁挂的牌子 | 状态码 | 回信 | `detail` 是什么 |
|---|---|---|---|
| **门卫**（Pydantic 校验） | `422` | `{"detail": [{"loc":..,"msg":..}]}` | **一摞**纸条，一栏一张 |
| **店里**（`服务.py` 里的 `try/except`） | `500` | `{"detail": "店里出事了：401 ..."}` | **一句话** |

页面先看 `响应.ok`，不是成功就把 `detail` 贴出来 —— 所以浏览器上永远是一句人话，
不会是一屏堆栈。

> 这个「两种 `detail` 形状不一样」是写完页面试空输入框时踩出来的：
> 门卫那份 `detail` 是列表，页面拿"一摞"去拼字符串，显示出来就是 `[object Object]`。

### 2. 拆词切出「跨词碎片」，把真答案挤出前三 ✅ 已修（2026-10-12 换成向量）

换向量以后不再拆词，这个问题从根上没了：同一批 10 道题，撞词版只命中 3 道，向量版命中 11 道。
下面这段是当年查根因的过程，留着当一个"看起来是程序坏了、其实是程序老实"的失败样本。

当年是怎么复现的（换向量前的老版本才会这样）：

```powershell
python 检索.py
```

问「闭包是什么」，返回的前 3 块**标题没有一个是关于闭包的**；
真正标题就叫「二、闭包」和「四、闭包 = 私有状态」的那两块，排在第 **4、5** 名。

两层原因叠在一起。

**第一层：跨词碎片拿到了高权重。**
第 1 步那个「每 2 个字切一刀」，`闭包` + `是什么` 会切出一个跨词的碎片 **`包是`**。
它本身毫无意义，但**因为罕见反而贵**：

| 词 | 权重 | 出现在 | 说明 |
|---|---|---|---|
| `包是` | **0.33** | 3 个块 | 跨词碎片，没意义 |
| `闭包` | **0.08** | 12 个块 | 真词 |

**碎片比真词贵 4 倍。** 于是「碰巧含这个碎片」的块压过了「真的在讲这个主题」的块。

**第二层：那 3 块为什么碰巧含这个碎片？**
不是碰巧。它们来自同一篇笔记（`2026-09-27.md`），而那篇在讲 `sys.argv` 时，
**拿「闭包是什么」当示例问句**：

```python
sys.argv = ["主程序.py", "闭包是什么"]     ← 这里就切出了「包是」
```

于是那一块里「闭包」出现了 **11 次**，**一个字都没讲闭包本身**。

> ⚠️ **检索器分不清「在讲闭包」和「只是提到了闭包这两个字」。**

**跑完整条线是什么样**：

```powershell
python 主程序.py "闭包是什么"
```

```
===== 问：闭包是什么，挑中 3 块 =====
  python-learning-2026-09-27.md:243  ### 做了什么
  python-learning-2026-09-27.md:259  ### 卡住的点：`" ".join(sys.argv[1:])` "不知道怎么拼好的"
  python-learning-2026-09-27.md:284  ### black：只改长相，不改意思
--------------------------------------------------
笔记里没有
```

**检索错了，模型没错。** 挑出来的 3 块确实没讲闭包，所以模型照实说了「笔记里没有」——
提示词里那句「如果笔记里没有，就说『笔记里没有』」把幻觉挡住了。
**这条失败看起来是"程序坏了"，其实是"程序老实"。**

> 顺带一个时间线：这个程序在 2026-09-25 第一次测「闭包是什么」时**是答对的**。
> 坏在 09-27 —— 那天新写的笔记在讲 `sys.argv` 时用了「闭包是什么」当示例问句，
> 把两篇本来不相干的笔记连到了一起。**语料一变，检索就可能坏，而它不会报错。**

**修法**：换成向量检索（embedding）。现在这版是刻意从零手写的，为的是看清每一步 ——
留在这里当一个具体的失败样本。

### 3. 没有缓存、也没有多轮

每一次提问都是全新的一次请求，不记得上一句。同一个问题问两遍就真的问两遍、花两次钱。

### 4. 向量缓存每次提问都重读一遍

`建块向量()` 每次被 `找相关()` 调用，都要从硬盘重读一遍 `_向量缓存.json`（6 MB）。
现在 454 块的量还顶得住，块再多就会变慢。

**修法**：服务启动时读一次、存在内存里复用。`web\服务.py` 已经在启动时算好一次 `块们`，
缓存却还是每问重读 —— 照同样的办法处理即可。

### 5. 网页版：空着输入框点「问」，显示的是 `[object Object]`

上面那张牌子表里说的第二行。`422` 的 `detail` 是一**摞**纸条，页面现在的写法
`"出事了：" + detail` 是照着一句话设计的，碰上"一摞"就只会吐出 `[object Object]`。

（`Ctrl+F5` 刷新页面会清空输入框，很容易撞上这个。）

**修法**：先判断 `detail` 是不是列表，是的话掏 `detail[0].msg`。

### 6. 网页版：提问是一次同步请求，前端一直干等

`fetch` 发出去之后要等模型答完（几秒到几十秒），这期间页面上只有两个字「想…」，
没有转圈、没有超时提示、也没法取消。服务端同理：一个请求占一个线程。

**修法**：前端加个超时和加载动画；服务端真要抗并发得换异步客户端或加队列。
