`with` 的核心只有一句：**它是 `try/finally` 的语法糖，负责让“清理代码”在离开代码块时自动执行，即使中途抛出异常也一样。**（这是我笔记 `python-learning-2026-08-14` 里总结的。）

## 1. 最常见的场景：打开文件

```python
with open("data.txt", "r", encoding="utf-8") as f:
    for line in f:
        print(line.strip())
# 出了这个块，f 已经自动 close 了，不用手动 f.close()
```

- **`as` 后面拿到的值是 `__enter__` 的返回值**，而不是 `with` 后面那个 `open(...)` 对象本身（对文件来说两者恰好相同）。
- `mode`：`"r"` 读取、`"w"` 覆盖写入（**先清空**）、`"a"` 追加写入、`"x"` 在文件已存在时报错（防止误覆盖）。
- 逐行读取用 `for line in f`，并配合 `strip()` 去掉换行符。
- **`encoding="utf-8"` 别忘**；这跟 `FileHandler` 忘了写 encoding 是同一个问题。

## 2. 自定义上下文管理器

只要类中实现了 `__enter__` 和 `__exit__`，这个类的对象就能放在 `with` 后面：

```python
class 计时器:
    def __enter__(self):
        self.start = time.time()
        return self          # ← 这个返回值给 as 后面的变量

    def __exit__(self, exc_type, exc, tb):
        print("耗时", time.time() - self.start)
        return False         # 返回 False/None：异常继续往外抛
```

- `__exit__` 的三个参数分别是“异常类型、异常对象、traceback”；如果没有异常，这三个参数都是 `None`。
- `__exit__` **返回 True 会吞掉异常**，返回 `False` / `None` 则让异常继续传播。
- 不管代码块里是正常结束还是中途抛异常，`__exit__` 都一定会执行；这就是“自动清理”的来源。

## 3. 两种已经在用的变体

**测试里**：`with self.assertRaises(ValueError) as 上下文:` 表示“下面这段代码必须报 ValueError”；`as 上下文` 用于接住异常，异常本体在 `上下文.exception` 里，要检查异常消息时使用 `assertIn(..., str(上下文.exception))`。

**pathlib 简写**：`文件.write_text(..., encoding="utf-8")` / `文件.read_text(encoding="utf-8")` 就是 `with open(...) as f: f.read()/f.write()` 的简写，同样别忘了 encoding。

## 4. 一句话记忆

> `with XXX as y:` 表示进入时执行 `XXX.__enter__()`，并把它的返回值绑定到 `y`；离开时无论正常结束还是抛出异常，都会执行 `XXX.__exit__(...)`。文件、锁、数据库连接、计时器都靠这个机制自动完成清理。
