字典要按值排序，做法是：先用 `.items()` 把字典拆成 `(键, 值)` 元组，再用 `key=lambda kv: kv[1]` 指定按值比较；如果直接比字典，比的是键。[python-learning-2026-09-03.md:213]

```python
d = {"苹果": 3, "香蕉": 1, "橘子": 2}

按值升序 = sorted(d.items(), key=lambda kv: kv[1])
# [('香蕉', 1), ('橘子', 2), ('苹果', 3)]

按值降序 = sorted(d.items(), key=lambda kv: kv[1], reverse=True)
# [('苹果', 3), ('橘子', 2), ('香蕉', 1)]
```

笔记里点出的两个注意点：[python-learning-2026-09-03.md:213]
- `kv` 是 `(键, 值)` 元组，`kv[1]` 才是值；如果写成 `kv[0]`，就会变成按键排序。
- 想结果仍然是字典，排完再套一层 `dict(...)`：`dict(sorted(d.items(), key=lambda kv: kv[1]))`。

补充两点通用规则：`reverse=True` 表示降序，默认升序；`key` 是“排序依据的转换器”，其参数是每个元素，返回值是拿什么来比较 [python-learning-2026-09-03.md:178]。另外 `sorted()` 返回新列表、不动原对象，`list.sort()` 才是原地改 [python-learning-2026-09-03.md:178]。

['[python-learning-2026-09-11.md:352 ## 下一步]', '- ⏳ **第 3 关：asyncio 与协程** —— 现代 Python 高并发主流', '  - `async`/`await` 语法、事件循环']
--------------------------------------------------
**核心判断标准很清晰：这个函数是 `async def`，还是普通的 `def`、会阻塞？** [python-learning-2026-09-14.md:107]

- 如果函数是 `async def`，也支持 `await`（例如各家 `AsyncClient`、LangChain 异步接口），就直接 `await` 它，交给事件循环处理，**用不着线程池**。
- 如果函数是普通 `def`，而且会阻塞（比如只有同步接口的某家大模型 SDK、`time.sleep`、同步 HTTP 请求），想把它放进协程里就必须用 `to_thread` 包一层——`to_thread` 返回一个可等待对象，同时**真的把同步函数丢到线程池里跑**，事件循环不会被堵 [python-learning-2026-09-14.md:107]。

```python
IO任务("1")                     # ❌ 同步调用：立刻跑完 + 堵死事件循环
asyncio.to_thread(IO任务, "1")  # ✅ 包成可等待对象，扔线程池里跑
```

两者到底差在哪：线程版是“3 个店员、3 个窗口”，店员接单后去后厨**站着等**，窗口空着；协程版是“1 个店员、1 个窗口”，把单子递进后厨就**立刻回头招呼下一位**，由事件循环（店员手上的记事本）记着哪单快好了。**全程只有一个线程**，所以并发版打印出来的线程名永远是 `MainThread` [python-learning-2026-09-14.md:59]。

再补充两个操作细节，都是你之前踩过的坑：
- `asyncio.gather(...)` 前面别忘了 `await`，否则【并发】那段一行输出都没有，任务会漏到下一题去跑 [python-learning-2026-09-14.md:152]。
- 别把 `async def` 的函数传给 `to_thread`——它在线程里执行只会返回一个协程对象，实际根本没跑，还会报 `RuntimeWarning: coroutine ... was never awaited` [python-learning-2026-09-14.md:152]。

顺带说一句：你笔记里的结论是**这条路线越往后越是“同步 SDK + `to_thread`”的天下**——主流 AI 框架（FastAPI、LangChain 异步接口、各家 `AsyncClient`）全是 `async` 的，所以默认优先选 asyncio，线程池只是用来把阻塞的同步代码接进 asyncio 的桥梁 [python-learning-2026-09-14.md:349]。
