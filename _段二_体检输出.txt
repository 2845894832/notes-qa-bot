```python

# [('香蕉', 1), ('橘子', 2), ('苹果', 3)]
```

| 任务特征 | 选谁 | 为什么 |
|---|---|---|
| 在**等**（网络、文件、数据库） | 线程或协程 | GIL 挡的是“算”，挡不住“等” |

所以具体到“asyncio 和线程池怎么选”：

- **IO 密集、并发量不大（几十个）**：两者都行，实测并列第一。`time.sleep` 会主动释放 GIL，线程在 IO 上完全够用；6A 里线程和协程都是 0.50s，串行 2.00s。[python-learning-2026-09-15.md:123]
- **并发量大（几百上千个连接/请求）**：选协程。协程一个只占几 KB，而线程要几 MB，且事件循环全程一个线程（打印出来永远是 `MainThread`）[python-learning-2026-09-14.md:59]。一句话原理是“维护一个任务列表，谁在等就挪到一边，谁好了就捡回来接着跑”，不用操作系统调度。
- **手上只有同步库**（比如很多大模型 SDK）：用协程，但阻塞的 `def` 函数必须用 `asyncio.to_thread(同步函数, 参数1, ...)` 包一层，扔进线程池运行，否则会阻塞事件循环。笔记里标了这是“以后做 AI 应用开发天天要用的模式”。[python-learning-2026-09-14.md:107]
  - 实测：直接调用阻塞函数要 **3.00 秒**，改成 `to_thread` 是 **1.01 秒**，被标为“最贴近求职方向”。[python-learning-2026-09-14.md:239]
- **如果它其实是在算**：两个都不选，改用多进程——6B 里 CPU 密集串行 3.97s、线程 3.88s（约等于没加速，GIL 的影响得到实测确认）、进程 0.62s，快 6.4 倍。[python-learning-2026-09-15.md:123]

另外两个坑也记一下：

- `asyncio.gather` 返回的顺序**等于传入顺序**，不是完成顺序（内部给每个协程编了号，结果放回对应位置）；而线程是谁先完成谁先来，顺序不可预测。[python-learning-2026-09-15.md:93]
- `gather` 遇到异常**不会**取消其他协程，要自动取消用 `asyncio.TaskGroup`。[python-learning-2026-09-15.md:93]

还有一条测试习惯：性能数字别信单次，同一个 CPU 任务连跑三次出了 1.64/2.14/4.51 秒，看比例别盯绝对值。[python-learning-2026-09-14.md:239]

**pip 是装包的工具，requirements.txt 是包清单文件。**

| 概念 | 命令 | 说明 |
|------|------|------|
| pip 装包 | `pip install 包名` | 装第三方库 |
| 导出依赖 | `pip freeze > requirements.txt` | 用 pip 把当前环境里的包生成清单 |
| 还原依赖 | `pip install -r requirements.txt` | 用 pip 按清单一键还原环境 |

也就是说：`pip freeze` 负责把你的环境"导出"成 requirements.txt，`pip install -r` 负责照这份清单把环境"复现"出来；这两个动作都由 pip 执行，requirements.txt 只是中间那份可提交、可分发的文本清单。

搭配 venv 时，流程通常是：每个项目一个独立环境，然后导出清单 → 在另一台机器/另一个环境里 `pip install -r` 还原。[python-learning-2026-09-02.md:187]
