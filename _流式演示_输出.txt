==============================================================
幕一：流式到底「流」的是什么 —— 假数据，一行一片
==============================================================
服务器发过来的原文长这样（注意每片之间有个空行）：
    data: {"choices":[{"delta":{"content":"闭"}}]}
    ←空行
    data: {"choices":[{"delta":{"content":"包"}}]}
    ←空行
    data: {"choices":[{"delta":{"content":"是"}}]}
    ←空行
    data: {"choices":[{"delta":{"content":"函数"}}]}
    ←空行
    data: [DONE]

切成一行一行来读：
    data: 之后的 39 个字符 → 一片正文：'闭'
    data: 之后的 39 个字符 → 一片正文：'包'
    data: 之后的 39 个字符 → 一片正文：'是'
    data: 之后的 40 个字符 → 一片正文：'函数'
    [DONE] ← 收工信号，它不是 JSON，别 json.loads

  ★ 三个动作：① 只认 `data: ` 开头的行  ② [DONE] 就停  ③ 剩下那段交给 json.loads
    你不用自己切逗号 —— 服务器已经帮你切成一行一个完整 JSON 了（这就是 jsonl 那招）。

==============================================================
幕二：同一句话，两条路，量三个数（真跑 2 次）
==============================================================
  非流式：干等了 2.12 秒，屏幕上才出现第一行字；
          然后 29 个字一下子全出来。

  流式：它到一片我打一片 →  闭包就像一个随身带着老家钥匙的人，走到哪儿都还能打开并使用老家的东西。

  一共收到 167 片；它先在肚子里打了 249 字草稿（reasoning_content，不显示）
  首包 0.28 秒   ← 网络这一趟有多快
  首字 1.83 秒   ← 用户第一次看见东西，真正决定「快不快」的数
  说完 1.97 秒   ← 跟非流式那个 2.12 秒是同一件事

  ★ 流式没有让模型变快，总耗时差不多；
    它只是把「要干等 2.12 秒」变成「1.83 秒就开始出字」。

幕三：带工具菜单 —— arguments 也是碎片（真跑 1 次）
==============================================================
  模型要伸手了，它把「申请单」拆成了 11 片发过来。前 3 片：
    {"index": 0, "id": "call_00_ET_6580EczcqHEe7EtxdBjv9076", "type": "function", "function": {"name": "search_notes", "arguments": ""}}
    {"index": 0, "function": {"arguments": "{"}}
    {"index": 0, "function": {"arguments": "\""}}
  后 3 片（注意：只有 index 和 arguments，连名字都没有）：
    {"index": 0, "function": {"arguments": "包"}}
    {"index": 0, "function": {"arguments": "\""}}
    {"index": 0, "function": {"arguments": "}"}}

  拼好的第 0 张申请：
    名字      search_notes
    参数原文  {"query": "闭包"}
    变成 dict {'query': '闭包'}   ← 拼完才能 json.loads

  ★ 碎片按 index 归队；name / id 只出现在开头那片，arguments 一片一片往上加。
    谁要是每片都 `申请 = 片`，最后只剩最后一个字符。

==============================================================
幕四：拆包拆完，跟整箱到货是同一个东西
==============================================================
  非流式拿到的 message 有哪些键：['content', 'reasoning_content', 'role']
  流式拼出来的 message 有哪些键：['content', 'role']

  非流式：回话.get('content') → '它把当时身边能用的东西记在心里，之后'…
  流式  ：回话.get('content') → '闭包就像一个随身带着老家钥匙的人，走'…

  ★ 所以 主程序.py 那个循环一行都不用改：它只认 回话['content'] 和 回话['tool_calls']。
    流式换掉的是「怎么到货」，不是「到货是什么」。
    ⚠️ 本子这件事也没变：流式拼出来的那条，照样要 append 回本子。

  唯一的真差别：思考过程在 reasoning_content 里，它不是正文。
  屏幕上要不要显示是你定的；拼回本子时只留 role / content / tool_calls 最干净。
