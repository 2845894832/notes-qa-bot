| 层 | 函数 | 收什么 | 返回什么 |
|----|------|--------|---------|

| 内层 | `wrapper(...)` | 调用参数 | 执行结果 |

字典按值排序的方法如下 [python-learning-2026-09-03.md:213]：

`sorted()` 直接比较字典时，比较的是**键**；如果要按**值**排序，就先用 `.items()` 把字典拆成 `(键, 值)` 元组，再用 `key` 取每一对的第 2 项：

```python
d = {"苹果": 3, "香蕉": 1, "橘子": 2}

按值升序 = sorted(d.items(), key=lambda kv: kv[1])
# [('香蕉', 1), ('橘子', 2), ('苹果', 3)]

按值降序 = sorted(d.items(), key=lambda kv: kv[1], reverse=True)
# [('苹果', 3), ('橘子', 2), ('香蕉', 1)]
```

**两个易错点**：
- `kv` 是 `(键, 值)` 元组，`kv[1]` 才是值；如果写成 `kv[0]`，就变成按键排序。
- 如果想保留成字典，排完后再用 `dict(...)`：`dict(sorted(d.items(), key=lambda kv: kv[1]))`。

关于 `key` 的工作原理：它是「排序依据的转换器」，并非「怎么比较」；`reverse` 默认为 `False`，表示升序，设为 `True` 表示降序 [python-learning-2026-09-03.md:178]。

# 虚拟环境（venv）是干嘛的

**一句话：每个项目一个独立的“小仓库”，避免不同项目的包版本相互冲突。**

核心 이유 [python-learning-2026-09-02.md:199]：

1. **为什么需要 venv**：全局只有一个 Python，所有项目的包都堆在一起，会造成**版本冲突**；venv 就是为每个项目准备一个独立的小仓库。
2. **venv 的本质**：复制一份 Python，再配一个独立的包目录（`Lib/site-packages`）；“激活”只是临时把 venv 里的 `Scripts` 目录放到 PATH 的最前面，所以命令会优先使用这个环境里的。
3. **`include-system-site-packages = false`** 是隔离的核心开关；改成 `true` 后，就能看到全局安装的包。
4. **pip 自动解析依赖**：装 `requests` 一个，会自动带上 urllib3、idna、certifi、charset_normalizer 四个。

常见操作 [python-learning-2026-09-03.md:39][python-learning-2026-09-02.md:187]：

| 激活 | `source myenv/Scripts/activate` |
| 退出 | `deactivate` |
| 导出依赖 | `pip freeze > requirements.txt` |
| 还原依赖 | `pip install -r requirements.txt` |
| 国内加速 | `pip install 包名 -i https://mirrors.aliyun.com/pypi/simple/` |

笔记里用餐馆类比：协程版是 1 个店员 1 个窗口，把单子递进后厨就**立刻回头招呼下一位**，谁在等就挪到一边、谁好了就捡回来接着跑，全程一个线程；线程版则是 3 个店员站着等，窗口空着。实测也验证了这一点：打印出来的线程名**永远是 `MainThread`**，并发版里「甲」「乙」交替出现，说明确实是在 `await` 处发生切换 [python-learning-2026-09-14.md:59]。
