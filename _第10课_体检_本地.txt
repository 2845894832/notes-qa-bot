按值排序的步骤：先用 `.items()` 把字典拆成 `(键, 值)` 元组，再用 `key` 取每一对中的第 2 项：

```python
d = {"苹果": 3, "香蕉": 1, "橘子": 2}

按值升序 = sorted(d.items(), key=lambda kv: kv[1])
# [('香蕉', 1), ('橘子', 2), ('苹果', 3)]

按值降序 = sorted(d.items(), key=lambda kv: kv[1], reverse=True)
# [('苹果', 3), ('橘子', 2), ('香蕉', 1)]
```
[python-learning-2026-09-03.md:213]

**两个常见错误**：
- `kv` 表示 `(键, 值)` 元组，其中 `kv[1]` 才是值；如果写成 `kv[0]`，就会变成按键排序。
- 如果想保留成字典，排序后再用 `dict(...)` 转换：`dict(sorted(d.items(), key=lambda kv: kv[1]))`。

补充两点规则：
- `key` 是“用来决定排序依据的转换器”，参数是每个元素，返回值是排序依据；`reverse=True` 用于降序，默认是升序。[python-learning-2026-09-03.md:178]
- 如果排序的是字典组成的列表，写法是 `sorted(students, key=lambda s: s["score"], reverse=True)`。[python-learning-2026-09-02.md:42]

笔记里有专门的“选择标准表”，可以直接照着选：

| 任务特征 | 选谁 | 为什么 |
|---|---|---|
| 在**等**（网络/文件/数据库） | 线程 或 协程 | GIL 挡算不挡等 |
| 在**算**（CPU 跑满） | **多进程** | 线程被 GIL 挡住，白忙 |
| 要**很多并发**（几百上千） | **协程** | 协程几 KB，线程几 MB |
| 手上是**同步库** | 协程 + `asyncio.to_thread` | 不堵事件循环 |
| 要**拿返回值** | 协程最省事 | 线程要自己收集，进程要走 Queue |
| 量**很小**（几个小文件） | **串行** | 起并发的开销比省下的还多 |

[python-learning-2026-09-14.md:292]

几个关键点：

- **协程版的事件循环机制**：维护一个任务列表，谁在等就挪到一边，谁好了就捡回来接着跑，全程一个线程（实测打印线程名永远是 `MainThread`，并发版里「甲」「乙」交替出现）[python-learning-2026-09-14.md:59]
- **同步函数要进协程，必须用 `asyncio.to_thread` 包一层**：凡是 `def`（不是 `async def`）而且会阻塞的函数，想扔进协程就必须用 `to_thread`。它返回可等待对象，同时真的把同步函数丢到线程池里跑，事件循环不会被堵。很多大模型 SDK 只有同步接口，就是这么包一层变异步的 [python-learning-2026-09-14.md:107]
- **线程的定位**：线程适合 IO 密集场景，线程共享内存，所以危险时必须加锁；GIL 会限制 CPU 计算 [python-learning-2026-09-11.md:210]

**一句话结论**：IO 密集且并发量不大 → 线程池够用；IO 密集且要几百上千并发、或已经在写 async 代码 → 协程；要调同步库 → `asyncio.to_thread` 混用；CPU 密集 → 这两者都不选，用多进程 [python-learning-2026-09-14.md:292]。
