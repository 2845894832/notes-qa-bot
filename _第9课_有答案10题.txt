字典按值排序的做法是**先把字典拆成 `(键, 值)` 元组，再用 `key` 取出每一对中的值来排序**：

```python
d = {"苹果": 3, "香蕉": 1, "橘子": 2}

按值升序 = sorted(d.items(), key=lambda kv: kv[1])
# [('香蕉', 1), ('橘子', 2), ('苹果', 3)]

按值降序 = sorted(d.items(), key=lambda kv: kv[1], reverse=True)
# [('苹果', 3), ('橘子', 2), ('香蕉', 1)]
```

两个要点：
- `sorted()` 直接比字典时比的是**键**，所以要先调用 `.items()`；`kv` 是 `(键, 值)` 元组，`kv[1]` 才是值，写成 `kv[0]` 就变成按键排序了 [python-learning-2026-09-03.md:213]。
- 如果想保留成字典，排完再套 `dict(...)`：`dict(sorted(d.items(), key=lambda kv: kv[1]))` [python-learning-2026-09-03.md:213]。

补充两点通用规则：`key` 只是把每个元素转换成用来比较的代表值，真正的比较规则仍由排序决定；`reverse=False` 默认升序，`True` 为降序 [python-learning-2026-09-03.md:178]。如果是「字典列表」按某个字段排序（比如按 `score`），写法是 `sorted(students, key=lambda s: s["score"], reverse=True)` [python-learning-2026-09-02.md:42]。

笔记里正好有这条判断规律，直接给你 [python-learning-2026-09-14.md:286]：

> **CPU 密集用进程，等 IO 用线程/协程，同步库用 `to_thread` 包一层。**

展开成选择顺序：

**1. 先看任务类型**
- **等 IO**（网络请求、调大模型 API、读写文件/数据库）→ 用 asyncio 协程；如果不想改造成异步，用线程池也可以 [python-learning-2026-09-14.md:286]
- **CPU 密集**（纯计算、压缩、大量数据处理）→ 用**进程**，因为线程被 GIL 卡住，只有进程各有一支笔才是真并行 [python-learning-2026-09-11.md:210]

**2. 如果选了 asyncio，但手里是同步库怎么办**
`asyncio.to_thread` 就是这座桥：它返回一个可等待对象，同时把同步函数丢进**线程池**里跑，事件循环不会被堵 [python-learning-2026-09-14.md:107]。规律要背下来：

> **凡是 `def`（不是 `async def`）而且会阻塞的函数，想扔进协程就必须用 `to_thread` 包一层。**

```python
IO任务("1")                     # ❌ 同步调用：立刻跑完 + 堵死事件循环
asyncio.to_thread(IO任务, "1")  # ✅ 包成可等待对象，扔线程池里跑
```

**3. 为什么协程能省线程**
协程是「一个线程，一堆小票」：单线程 + 事件循环维护任务列表，谁在等就挪一边，谁好了捡回来接着跑，全程一个线程（实测线程名永远是 `MainThread`）[python-learning-2026-09-14.md:59]。所以 IO 密集场景下协程比线程池更轻，不用几百个线程。

**4. 对你的实际场景**
笔记里特别标了：「这是你以后做 AI 应用开发天天要用的模式」——很多大模型 SDK 只有同步接口，就是 `to_thread` 包一层变异步 [python-learning-2026-09-14.md:107]，而 asyncio 这一关本身就和「调大模型 API、流式输出」最贴近 [python-learning-2026-09-11.md:352]。

一句话决策：**能异步就异步（IO），改不动就 `to_thread` 丢线程池，纯算就用进程。**

**关系一句话：pip 是装包的工具，requirements.txt 是它读写的一份依赖清单。**

**分工**
- **pip**：负责装包，比如 `pip install requests`（装第三方库）[python-learning-2026-09-02.md:187]。也可以指定镜像加速：`-i https://mirrors.aliyun.com/pypi/simple/` [python-learning-2026-09-02.md:187]。
- **requirements.txt**：文件本身不干活，只是记录“这个项目用了哪些包、什么版本”；依靠 pip 来生成和读取。

**两个方向的用法**
| 操作 | 命令 | 含义 |
|---|---|---|
| 导出 | `pip freeze > requirements.txt` | 把你当前环境里的包清单写入文件 |
| 还原 | `pip install -r requirements.txt` | pip 照这份清单一次性装回来 |

出处：[python-learning-2026-09-03.md:39]、[python-learning-2026-09-02.md:187]

**和 venv 的配合方式（这才是这两个工具的典型使用场景）**
在项目自己的 venv 里安装需要的包，再用 `pip freeze` 导出清单；换台机器或给别人时，用 `pip install -r requirements.txt` 一键还原同一套环境。笔记里练过一遍：创建 venv、装 requests、导出 requirements.txt，全程跑通 ✅ [python-learning-2026-09-02.md:220]。

一句话记：**pip 负责操作包，requirements.txt 是写下来的结果，恢复时需要 pip 来读取它。**
