# C1 讲解 —— 一步一步来

---

## 第 1 步：让一家店在网上开起来

### 一个类比，从头用到尾

**服务（service）= 一家开在网上的店。**

- 普通脚本：你敲 `python xxx.py`，它干完活就关门走人 —— 像个**上门师傅**，修完水管就撤。
- 服务：你敲命令把它**点着**，它就一直在那儿等着，谁来了招呼谁 —— 像个**开了门的店**。

这个区别是这一整步唯一要记住的东西。后面所有东西都挂在这上面。

---

### 店里的三样东西

| 店里的说法 | 代码里的说法 | 在 `服务.py` 里是哪一行 |
|---|---|---|
| 柜台（客人从哪个口子递话） | 路由 | `@app.get("/")` |
| 客人递进来的话 | 请求 | 浏览器访问 `/` |
| 你递回去的东西 | 响应 | `return {"消息": "店开着呢"}` |

现在这家店只有**一个柜台**，就在店门口 `/`，只会做一件事：递一句话回去。

---

### 跑起来

```bat
cd "D:\CC Switch\问答机器人\web"
python -m uvicorn 服务:app --reload
```

**这行命令在念三个东西：**

- `服务` —— 去哪个文件里找（`服务.py`）
- `app` —— 找文件里叫 `app` 的那个东西（`app = FastAPI()` 那一行）
- `--reload` —— 改完文件自动重启，不用手动关了再开

---

### 跑起来之后你会看到什么

屏幕上会停住不返回，最后一行大致长这样：

```
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
```

**注意：命令没有结束。** 光标不会回到 `D:\CC Switch>` 那个提示符，因为店开着，它得一直站那儿。

`127.0.0.1:8000` 就是这家店的地址 —— 只有你自己这台电脑能进（`127.0.0.1` = 本机）。

浏览器里打开 `http://127.0.0.1:8000`，你会看到：

```json
{"消息":"店开着呢"}
```

---

### 一个小实验（做完就懂"服务活着"是什么意思）

1. 店开着的时候，去浏览器里刷新几次 —— 每次都能打开，**而你没有重新敲过命令**。
2. 回到终端按 `Ctrl+C`。
3. 再刷新浏览器 —— **打不开了。**

因为店关了。这就是"服务"和"脚本"最大的不同：

> **脚本是一次性的，服务是一直站着的。**
> 终端窗口一关，店就关门；这个命令一直挂着，店才一直开着。

## 第 2 步：加一个「问事处」柜台

### 服务的本质，就一句话

> **收一个东西，回一个东西。**

第 1 步那个柜台只会**回**（`/` 什么都不用给，它就回一句话）。
现在加的这个会**收**。

### 新柜台长这样

```python
@app.get("/问")
def 问(问题: str):
    答案 = 主程序.回答一个问题(问题, 块们)
    return {"答案": 答案}
```

四行，一行干一件事：

| 行 | 干什么 |
|---|---|
| `@app.get("/问")` | 挂块新牌子：**这个柜台在 `/问`** |
| `def 问(问题: str)` | 括号里写的，就是**要顾客递进来的东西** |
| `答案 = 主程序.回答一个问题(...)` | 转手交给 C3 去办（业务逻辑一行没重写） |
| `return {"答案": 答案}` | **递回去** |

### 括号里的名字 = 顾客要填的那一栏

`def 问(问题: str)` 里的 `问题`，FastAPI 会去网址的 `?` 后面找 `问题=` 这一栏，取出来交给你：

```
http://127.0.0.1:8000/问?问题=闭包是什么
                        └──┬──┘ └─────┬─────┘
                  跟括号里的名字一字不差  这就是「问题」的值
```

**名字对不上就取不到** —— 这是最常踩的坑。

### 那三行 sys.path 是干嘛的

```python
sys.path.insert(0, r"D:\CC Switch\问答机器人")
import 检索
import 主程序
```

Python `import` 的时候，只会去几个**固定的地方**找文件。C3 那三个文件在别的文件夹里，得先告诉 Python 一声「那个文件夹也算数」—— `sys.path.insert` 就是干这个的。

### 笔记只在**开店时**读一次

```python
块们 = 检索.可用块()
```

这行**没写在函数里面**，所以它只在服务启动时跑一次。之后每来一个顾客都用现成这一份，不用每次都重新翻笔记。

（顺带解释了 `--reload` 的一个副作用：你一改文件，店就重开，笔记就重读一遍。）

### ⚠️ 顺手改了 C3 一行，先说一声

原来 `回答一个问题` 只会**打印**答案，不会**交出来**：

```python
def 回答一个问题(问题: str, 块们: list[dict]) -> None:   # 原来是 None
    ...
    print(答案)
    return 答案        # ← 新加的这一行
```

服务要把答案递回去，就得先**拿到手**。`print` 还留着，命令行用起来跟以前一模一样。

> 这正好是每日题台账里反复出现的那个毛病「**返回值没接住**」的正面例子：
> 你调一个函数，它不说 `return`，你手里就是空的，想递出去也递不了。

### 试试看

服务开着的时候，浏览器地址栏直接打这一整行（等几秒）：

```
http://127.0.0.1:8000/问?问题=闭包是什么
```

- [ ] 能说出 `def 问(问题: str)` 里的 `问题` 是从网址的哪个位置取出来的
- [ ] 能说出 `块们 = 检索.可用块()` 为什么写在函数外面

## 第 3 步：门口加个门卫

第 2 步的柜台有个漏洞。先把它量出来 ——
在 `/docs` 里往 `/问` 发**不填**和**填个空的**，是两回事：

| 怎么发 | 状态码 | 结果 |
|---|---|---|
| 打 `/问`（**这栏不填**） | **422** | `Field required`，连函数都没进 |
| `/问?问题=`（**填了，是空的**） | **200** | 照收，还**真去问了一次模型** |

**一句话：FastAPI 白送的那层，只查「这栏填没填」，不查「填的东西算不算数」。**
空字符串也是一串字符，它管不着。→ 这就是要加门卫的理由。

### 门卫手上先要有一张「单子模板」

模板 = **一个类**。这个类不干别的，只描述"一张合格的提问单子长什么样"：

```python
from pydantic import BaseModel, Field

class 提问(BaseModel):
    问题: str = Field(min_length=1, max_length=200)
```

- `问题: str` —— 这栏得是**字符串**。
- `Field(min_length=1, max_length=200)` —— 再贴两道规矩：**最少 1 个字、最多 200 个字**。

⚠️ 约束写在**等号右边**（`Field(...)` 是赋值进去的，不是写类型里）。

### 柜台跟着改三处

```python
@app.post("/问")                     # ① get  →  post
def 问(单子: 提问) -> dict:            # ② 问题: str  →  单子: 提问
    答案 = 主程序.回答一个问题(单子.问题, 块们)   # ③ 问题  →  单子.问题
    return {"答案": 答案}
```

**②是关键：FastAPI 靠参数的类型决定"去哪儿找"** ——

| 参数长这样 | 它去哪儿找 |
|---|---|
| `问题: str` | 去**网址**上找（`?问题=xxx`） |
| `单子: 提问`（一个 `BaseModel`） | 去**请求体**里找（递进来的 JSON 单子） |

### 地址栏测不了了

第 2 步是靠地址栏测的（打一行网就能看答案）。**改成 POST 之后不行了** ——
地址栏只会发 GET，递不了单子。得去 `/docs` 里那个 `Try it out` 填 `{"问题": "..."}` 再 Execute。

### 门卫拦下来的时候，你函数那边什么都不知道

这是第 3 步最该记住的一句。用**能数的数**看：一次发 5 张单子，终端上长这样 ——

```
INFO:  127.0.0.1 - "POST /%E9%97%AE HTTP/1.1" 422 Unprocessable Content   ← {"问题": ""}
INFO:  127.0.0.1 - "POST /%E9%97%AE HTTP/1.1" 422 Unprocessable Content   ← {"问题": "x" 乘 300}
INFO:  127.0.0.1 - "POST /%E9%97%AE HTTP/1.1" 422 Unprocessable Content   ← {} 什么都没填
INFO:  127.0.0.1 - "POST /%E9%97%AE HTTP/1.1" 422 Unprocessable Content   ← {"问题": 123}
===== 问：闭包是什么，挑中 3 块 =====                                        ← 只有这条进了函数
--------------------------------------------------
笔记里没有。
INFO:  127.0.0.1 - "POST /%E9%97%AE HTTP/1.1" 200 OK
```

**`=====` 那行只出现 1 次，而单子递了 5 张。**
那 4 张不合格的，你的函数**一次都没被调用** —— 门卫在门外就把人打发走了。

> ⚠️ 所以"校验"不是"进了函数再检查一下"，而是**在门外就结束了**。
> 对比一下第 9 轮每日题的日志：那边是"坏行也进函数，进去之后记一笔 warning 跳过" ——
> **这次是根本进不来。**两件事长得像，位置完全不同。

### 门卫拦人的时候说什么

拦下来扔的是 `ValidationError`。四种情况的原话：

| 递什么 | 状态码 | 门卫的理由 |
|---|---|---|
| `{"问题": ""}` | 422 | `String should have at least 1 character` |
| `{"问题": "x" * 300}` | 422 | `String should have at most 200 characters` |
| `{}` | 422 | `Field required` |
| `{"问题": 123}` | 422 | `Input should be a valid string` |

在页面上看到的就是 `{"detail": [{"loc": ["body", "问题"], "msg": "...", ...}]}` ——
`loc` 是**哪一栏**，`msg` 是**为什么**。

### 这一步你自己踩的两个坑

1. **试错的代码写在了最外层**（`问("问题": "")` 三行）——
   它是语法错，**整个文件都加载不了**，所有报错全被它挡住。
   想试错误 → **写进测试**；模块级只放声明，别放会跑的代码。
   （每日题台账里 09-27 也栽在同一个地方。）
2. **`-> str/BaseModel:`** —— 那个斜杠 Python 当**除法**算，两个类型除起来直接报错。
   要写就写 `-> dict`（这函数返回的正是一个字典）。

### 第 3 步的自查

- [ ] 能说出 `def 问(单子: 提问)` 里的类型改成 `BaseModel` 之后，FastAPI 去哪儿找数据

- [ ] 能说出"多给一栏"会怎样（Pydantic 默认**不管，直接丢掉**）

## 第 4 步：门口挂块牌子 + 开扇展示窗

这一步是两件事，一样一样来：

- **4-A 异常翻译**（服务端）：店里出事时，门口得挂块**有字**的牌子
- **4-B 展示窗**（浏览器端）：开一个页面，别人打开就能问

---

### 4-A · 先量现状（先看到，再讲）

把钥匙改坏，起服务，用浏览器发一次请求。**两个人看到的东西不一样：**

| 谁 | 看到什么 |
|---|---|
| **顾客**（浏览器/前端） | `Internal Server Error` —— 五个词，一点原因都没有 |
| **你**（起服务的终端） | 一屏堆栈，最后一行写得清清楚楚：`401 Client Error` |

> **里面知道的，外面一个字都没说。** 这就是要补的洞。

（对比第 3 步：那次门卫拦人，回的是 `{"detail": [...]}` —— **外面是看得见的**。
门外拦的，外面看得见；门里炸的，外面看不见。）

---

### 挂牌子这个动作

```python
from fastapi import FastAPI, HTTPException      # ① 多带一个名字进来
...
@app.post("/问")
def 问(单子: 提问) -> dict:
    try:
        答案 = 主程序.回答一个问题(单子.问题, 块们)
        return {"答案": 答案}
    except RuntimeError as 错:                   # ② 接住
        raise HTTPException(                     # ③ 挂块牌子
            status_code=500,
            detail=f"店里出事了：{错}",
        )
```

`HTTPException` 拆成三块看：

| 写法 | 意思 |
|---|---|
| `HTTPException(...)` | **"往门口挂一块牌子"**这个动作 |
| `status_code=500` | 牌子上那个数 —— **5 开头 = 店里的事，4 开头 = 顾客的事** |
| `detail="..."` | 牌子上那行字 —— 会被 FastAPI 装成 `{"detail": "..."}` 发出去 |

---

### 两个空怎么填（这一步唯一要动脑的地方）

#### ① `except ______` 填什么？

**猜没用，翻代码。** 去 `D:\CC Switch\问答机器人\问模型.py` 里翻 `问一句`，
看它最后 `raise` 的是什么 → `RuntimeError`。

> ⭐ **你在哪一层接，取决于下面那一层扔的是什么。**
> 你写的 `except` 只挡得住**它点名的**那种异常；别的异常从旁边**直接穿过去**，
> 门口就还是光秃秃那五个词。（后面收工记录里的第 5 条会真演一次给你看。）

#### ② `status_code` 填多少？

第 3 步的 422 是**门卫**发的 —— 那是"你单子填得不对"，**顾客的锅**。
这次是**店里自己出了事**（钥匙不对、模型连不上）→ **5 开头**，填 `500`。

### 4-B · 页面

#### 服务端：怎么"端出一个文件"

```python
from fastapi.responses import FileResponse

@app.get("/")
def 首页():
    return FileResponse("页面.html")
```

`FileResponse` = **"把这个文件端出去"**。
`"页面.html"` 是**相对路径** —— 相对于你启动服务时所在的目录，
所以还是得先 `cd "D:\CC Switch\问答机器人\web"` 再启动（跟 `expenses.json` 一个道理）。

> ⚠️ **这一版后来改掉了** —— 见下面「搬家」一节。相对路径"碰巧站对了才work"，
> 换成 `Path(__file__)` 之后站在哪儿启动都对。

⚠️ **页面文件不用重启服务。** `--reload` 只盯着 `.py`；改 HTML 只要在浏览器 **`Ctrl+F5`** 强刷。

#### 浏览器端：JS 就是 Python 换了个马甲

| 干的事 | Python | JS |
|---|---|---|
| 发请求 | `requests.post(...)` | `fetch(...)` |
| 拆回信 | `json.loads(...)` | `.json()` |
| 取一栏 | `d["答案"]` | `d.答案` |

一个新语法：**变量前面加 `const`**。

#### 页面的活只有两句

```js
const 响应 = await fetch("/问", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ 问题: 问题框.value }),   // ← 装问题
});

const 数据 = await 响应.json();                   // ← 拆回信
答案区.textContent = 数据.答案;                    // ← 贴上屏
```

`await` 就是**"在这一行等它回来"**（发网络请求要花时间）。

#### 页面也得**先看牌子**

`响应` 身上有个东西叫 `响应.ok`：成功 `true`，出事 `false`。

```js
if (响应.ok === false) {
  答案区.textContent = "出事了：" + (await 响应.json()).detail;
  return;          // ⚠️ 别删 —— 出事了就不该再往下掏「答案」
}
```

---

### 收工记录：这一步真踩到的 5 个坑（都实跑验过）

#### 1️⃣ `问题框` ≠ `问题框.value`

- `问题框` = **那个输入框这个东西本身**
- `问题框.value` = **里面打的字**

填成 `问题框`，发出去的单子就是 `{"问题": {}}` —— **空壳，字没带上** → 门卫退回 **422**。
页面症状：`undefined`。

#### 2️⃣ JS 里没有 `f"..."`

`f"{x}"` 是 Python 的。JS 拼字符串就用 `+`。
而且这个错的**症状很特别** —— 见下一条。

#### 3️⃣ 认准两个症状，一眼分清哪边坏了

| 你看到的 | 说明 |
|---|---|
| 页面显示 `undefined` | JS **跑完了**，只是没掏到东西 |
| 点「问」**一点动静都没有**（连"想…"都不出现） | JS **压根没跑起来** —— 语法错，整段 `<script>` 全废 |
| 页面**永远停在**「想…」 | JS 跑起来又**中途炸了**，后面的行再也没轮到 |

第 3 种是最后那次卡住的样子（原因见第 5 条）。
自己验语法不用开浏览器：

```bat
node -e "const s=require('fs').readFileSync('页面.html','utf8');new Function(s.split('<script>')[1].split('</script>')[0])"
```

#### 4️⃣ **两种"牌子"长得不一样**

这一点是收工时顺手挖出来的，很值钱：

| 谁挂的牌子 | 回信 | `detail` 是什么 |
|---|---|---|
| **500** —— 你自己 `raise HTTPException(detail="一句话")` | `{"detail": "店里出事了:401 ..."}` | **字符串**（一句话） |
| **422** —— 门卫 Pydantic 自动生成 | `{"detail": [{"loc":..,"msg":..}]}` | **列表**（一栏一张纸条） |

所以页面上写 `"出事了：" + detail`，**只在 500 那封信上好看**；
碰上 422，拿"一摞"去拼字符串 —— JS 只能吐出 `[object Object]`。

> 实测：框里**不打字**直接点「问」→ 踩的是 `min_length=1` → 422 → `[object Object]`。
> ⚠️ **刷新页面会把输入框清空**，别忘了重新打字。

#### 5️⃣ 钥匙不能是中文（这条是我出的错，记下来别再踩）

```bat
set DEEPSEEK_API_KEY=坏的        ← 炸
set DEEPSEEK_API_KEY=bad        ← 好
```

真凶：

```
UnicodeEncodeError: 'latin-1' codec can't encode characters in position 7-8
```

**为什么**：钥匙不是装在信封**里面**的，是**写在信封上**的（HTTP 请求头）。
信封只认拉丁字母，中文塞不上去 —— `requests` 当场炸，**根本没轮到问模型**。

**后果有两层：**

1. 飞出来的是 `UnicodeEncodeError`，**不是你点名的 `RuntimeError`** →
   从 `except` 旁边直接穿过去 → 门口还是光秃秃那五个词。
2. uvicorn 那份回信是**纯文本** `Internal Server Error`，**不是 JSON** →
   页面 `await 响应.json()` 当场炸 → JS 没接住，函数**停死在那一行** → 页面永远停在「想…」。

#### ✅ 最终验收（实跑）

```
出事了：店里出事了:这个错误再试也没用：401 Client Error: Authorization Required ...
```

**一句话，不是一屏堆栈。** 而且它是**三层拼的**：

```
出事了：                        ← 页面这一层加的
店里出事了:                     ← 服务.py 里 detail= 写的那半句
这个错误再试也没用：401 ...      ← 问模型.py 里 raise 的原话
```

能出现在你在浏览器里，说明它**真的穿了两次网线过来**。
