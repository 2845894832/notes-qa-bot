## 一、迭代器（iter / next 协议）

### 学了什么

| 概念 | 代码 | 一句话 |
|------|------|--------|
| 可迭代对象 | 列表 / 字典 / 字符串 / 文件对象 | 能被 for 遍历，有 `__iter__` |
| 迭代器(游标) | `it = iter(列表)` | 用 iter() 拿到的"游标" |
| 取下一个 | `next(it)` | 游标前进一格、取一个 |
| 结束信号 | `StopIteration` | 走完抛这个异常，for 靠它停 |

### 关键收获

- `for x in 列表` 的本质 = 不断 `next()`，直到捕获 `StopIteration` 停下
- 迭代器是一台"会记住自己走到哪"的机器：`__next__` 每次干两件事 —— **返回当前 + 推进状态**（缺一不可，不推进就死循环）
- 自己写迭代器类：`__iter__` 返回 self + `__next__`（返回当前、推进、到头 raise StopIteration）

## 二、生成器（yield）⭐ 本课重点

### 学了什么

| 概念 | 代码 | 一句话 |
|------|------|--------|
| yield | `yield 值` | 交出一个值 + 函数暂停记住现场 |
| 生成器函数 | 函数体里有 yield | 调用它**不执行函数体**，返回生成器对象 |
| 暂停-恢复 | `next(g)` | 每次 next 跑到 yield 暂停，下次接着跑 |

### 关键收获

- **yield = return 一个值 + 暂停 + 下次接着来**；return 只有"给值"，函数交完就死
- 三个意义：① 省内存（要一个算一个）② 能表达无限序列 ③ 流水线（多个生成器串联）
- `a, b = b, a + b` 是**同时赋值**：右边先用旧值算完，再一次性赋给左边
- 大模型"流式输出"（打字机式）就是生成器思路 → 对 AI 应用很重要

## 三、生成器表达式 + itertools

### 生成器表达式
- 列表推导式 `[]` 换成 `()` 就是生成器表达式，惰性、省内存
- `sum(x*x for x in range(...))` 不占内存（列表版会先造整个列表）

### itertools

| 函数 | 作用 |
|------|------|
| `count(n)` | 无限计数 |
| `islice(it, n)` | 切片前 n 个 |
| `chain(a, b)` | 串联 |
| `combinations(x, k)` | 组合（不管顺序） |

## 踩坑 / 注意点

- `yield` / `return` 之后的 `pass` 是死代码，删掉（连续两次犯这个）
- 去行末换行用 `line.strip()`，别用 `line.rsplit('\n', 1)[0]` 这种绕的
- `__next__` 里"先减再 +1 补回"太绕，直白写法：先存 `n = self.current`，再减，返回 n
- `a = None` 后面又覆盖，第一行冗余
- `count()` 是无限迭代器，单独用会死循环，必须配 `islice`
- `combinations` 是组合，`('A','B')` 和 `('B','A')` 算同一个

## 今日主题补充：作用域与闭包（函数进阶 · 第 1 课）

### 一、LEGB 规则（找变量的顺序）

| 层级 | 名字 | 含义 |
|------|------|------|
| L | Local | 当前函数内 |
| E | Enclosing | 外层函数（嵌套函数） |
| G | Global | 模块级 |
| B | Built-in | 内置名字 |

- 口诀：从内往外找，找到谁用谁（L → E → G → B）
- 变量是谁在用，就站在谁的位置从内往外看

### 二、闭包

- **闭包 = 内层函数 + 它捕获的外层变量**
- 外层函数已返回，被捕获的变量还活着（和生成器"暂停-恢复"同一机制）
- **返回的是函数对象本身**（`return inner`），不是调用结果（`return inner()`）
- 函数工厂：`make_power(n)` —— 同一模板，配不同"记忆"造不同函数

### 三、nonlocal / global

| 关键字 | 作用 | 场景 |
|--------|------|------|
| nonlocal | 改外层函数（Enclosing）变量 | 闭包里改被捕获的变量 |
| global | 改全局变量 | 函数里改模块级变量 |

- 只读不用声明；**修改**才要 nonlocal/global
- 否则 Python 当成新建局部变量，报 UnboundLocalError

### 四、闭包 = 私有状态（封装）

- 银行账户：balance 藏在闭包里，外面只能通过 deposit/withdraw/get_balance 操作
- 用 nonlocal 即可，不需要 class/self

## 踩坑 / 注意点

- `a = +1` 是设成正 1，累加要 `a += 1`
- return 函数别带括号：`return inner` ≠ `return inner()`
- f-string 用花括号 `{变量}`，不是方括号 `[变量]`
- 引号嵌套会 SyntaxError（f"..." 里别再用同种引号）
- 闭包封装状态不用 class/self，用 nonlocal
- 中文乱码：终端 GBK vs 文件 UTF-8，运行加 `PYTHONIOENCODING=utf-8`

### ⚠️ 巩固练习暴露的反复错误（重点记，各犯过两次）

- 顶层 `print(x)` 读"全局"，不是"外层"（`outer` 已 return，局部变量销毁了，外面碰不到）
- `UnboundLocalError` 原因：函数里对变量赋值 → 变量被当局部 → `+=` 右边读"还没定义的局部变量"
- `=+` 要写成 `+=`（加号在等号左边）；内部函数要 `return` 值，不然拿到 None

## 流水线澄清（重新讲解后理解）

- 核心洞察：流水线版是「数据一个接一个流过整条线」，列表版是「一批批算完、堆起来再搬下一步」
- 执行顺序：下游要一个 → 上游才产一个（从外往里"拉"，不是从里往外执行）
- "中途不落地" = 中间不产生完整列表 = 省内存（处理大文件/大数据的关键）
- 类比：工厂传送带（零件一个接一个过工位）vs 没有传送带（整堆搬运）
- 演示文件：`pipeline_demo.py`

## 今日主题补充：装饰器（函数进阶 · 第 2 课）

### 核心概念

- 装饰器 = 接收函数、返回函数的函数（闭包的应用）
- `@decorator` 语法糖 = `func = decorator(func)`（包函数是动作，@ 是甜写法）
- `func` = 被装饰的原函数（函数对象）；`func()` = 调用它
- `*args` / `**kwargs`：接收任意参数，原样转发给原函数

### 三层嵌套（带参数装饰器）

| 层 | 函数 | 收什么 | 返回什么 |
|----|------|--------|---------|
| 外层 | `repeat(n)` | 装饰器参数 | decorator |
| 中层 | `decorator(func)` | 被装饰函数 | wrapper |
| 内层 | `wrapper(...)` | 调用参数 | 执行结果 |

### ⚠️ 核心踩坑（反复犯）

- 装饰器**外层**要 `return wrapper`（函数对象），**不是** `return func(...)`（调用结果）
- wrapper **内层**要 `func(*args, **kwargs)` 转发参数，**不是** `func()`（会丢参数）
- `except` 必须跟在 `try` 后面
- `functools.wraps(func)` 保留原函数名字/文档
