# 第一部分：asyncio 与协程（第 3 关）

## 一、一句话讲清三把武器

| | 比喻 | 谁在调度 | 单个开销 | 要不要锁 |
|---|---|---|---|---|
| **线程** | 多雇几个店员 | 操作系统内核 | 约 1MB 栈 | 要（抢占式） |
| **进程** | 再开一家分店 | 操作系统内核 | 更贵，启动约 0.1 秒 | 不用（内存隔离） |
| **协程** | 一个店员，会「挂单」 | Python 自己（事件循环） | 几 KB 对象 | 基本不用（协作式） |

**协程的全部精髓在「挂单」两个字**：把单子递进后厨，立刻回头招呼下一桌。

> 核心洞察：**线程在等 IO 的时候，其实什么也没干**——它就是被挂起了，可栈还占着。
> 既然只是"等"，为什么要花一个线程去等？

## 二、卡片模型（本关的核心，也是最大的坎）

**这是本关唯一必须记牢的东西：**

> **调用一个 `async def` 函数，不会做任何事。它只是给你开了一张「待办小票」。**

```python
fetch("A")                     # 只开票，函数体一个字都不执行
await fetch("A")               # 开票 + 递进后厨 + 我在这儿等它出锅
await asyncio.gather(f(), g()) # 两张票一起递进去
asyncio.create_task(f())       # 递进去，但转身就走，不在这儿等
```

| 你写的 | 结果 |
|---|---|
| `f()` | 造票，**没跑** ❌ |
| `await f()` | 造票 + 立刻跑完 ✅ |
| `await asyncio.gather(f(), f(), f())` | 三张一起跑 ✅ |
| `asyncio.create_task(f())` | 造票 + 立刻交上去，**但自己不等** |
| `asyncio.gather(f(), f())`（没 await） | 交上去了但你没等，**任务会泄漏到后面接着跑** ⚠️ |
| `asyncio.to_thread(...)`（没 await） | 造票就扔了，**真的什么都没跑** ⚠️ |

⚠️ **两种「没 await」的后果不一样，这个区别很重要：**

- `f()` / `to_thread(...)` 没 await → **真的没跑**，最后报 `RuntimeWarning: coroutine was never awaited`
- `gather(...)` 没 await → **跑了**！`gather` 内部会自动把协程包成 Task 交给事件循环，只是你不等它，它会**泄漏到后面的代码里继续跑**

**这句警告翻译成人话：**

> `RuntimeWarning: coroutine was never awaited` = **「你票开了，没递。」**

（跟生成器是同一个机制：生成器函数调用返回生成器对象，不迭代就不跑。协程本质就是生成器穿了件马甲。）

## 三、事件循环

类比**餐馆**：

| | 线程版 | 协程版 |
|---|---|---|
| 配置 | 3 个店员，3 个窗口 | 1 个店员，1 个窗口 |
| 顾客点单 | 店员 A 接单，去后厨**站着等**，窗口空着 | 店员把单子递进后厨，**立刻回头招呼下一位** |
| 谁记着"哪单快好了" | 操作系统 | **事件循环**（店员的记事本） |

`asyncio.run(main())` = **开门营业**：启动事件循环，把 main 跑起来，跑完关门。

**一句话：维护一个任务列表，谁在等就挪到一边，谁好了就捡回来接着跑。全程一个线程。**

实测证明（题 2）：打印出来的线程名**永远是 `MainThread`**，而且并发版里「甲」「乙」是**交替**出现的——说明确实在 `await` 处发生了切换。

## 四、`gather` 与 `create_task`

两个都是"把票递进后厨"，区别在**你等不等**：

| | 递票 | 我要不要站这等 |
|---|---|---|
| `await asyncio.gather(票1, 票2)` | 一起递 | **站着等全部做完**，一次性拿到结果列表 |
| `asyncio.create_task(票1)` | 单独递 | **转身就走**，等会儿再回来问 |

- `gather` = **自动挡**，创建 + 等待一步到位
- `create_task` = **手动挡**，先全点上火（让它们先烧起来），再逐个回来取

⚠️ **`create_task` 必须写在 `await` 之前**。写完一张票就 `await` 一张 → 退化成串行。

## 五、本关最大的坑：阻塞事件循环

**事件循环只有一个线程。** 你在协程里写同步阻塞调用，等于把调度员本人按在椅子上——所有任务全部停摆。

```python
async def 坏的():
    time.sleep(1)            # ❌ 店员跑去后厨干等 1 分钟，全店停摆

async def 好的():
    await asyncio.sleep(1)   # ✅ 票递进去，出来招呼下一桌
```

| | `time.sleep(1)` | `await asyncio.sleep(1)` |
|---|---|---|
| 谁在等 | 整个**线程**被占着躺 1 秒 | 只有**这个协程**在等 |
| 等的时候线程在干嘛 | 被占死，谁也别想用 | 立刻去跑别的任务 |
| 类比 | 我躺下了 | 我挂个号，你先忙别的 |

### 救生圈：`asyncio.to_thread`

**规律（背下来）：**

> **凡是 `def`（不是 `async def`）而且会阻塞的函数，想扔进协程就必须用 `to_thread` 包一层。**

```python
asyncio.to_thread(同步函数, 参数1, 参数2)
#                ↑ 函数名不加括号，后面跟它的参数
```

`to_thread` 返回一个**可等待对象**，同时真的把同步函数丢到**线程池**里跑，事件循环不会被堵。

```python
IO任务("1")                     # ❌ 同步调用：立刻跑完 + 堵死事件循环
asyncio.to_thread(IO任务, "1")  # ✅ 包成可等待对象，扔线程池里跑
```

> **这是你以后做 AI 应用开发天天要用的模式**：很多大模型 SDK 只有同步接口，就是这么包一层变异步的。

## 七、第 3 关踩坑记录

1. **`asyncio.gather(...)` 前面忘记 `await`**（题 2b，反复 3 轮没改掉）
   - 症状：【并发】那一段一行输出都没有，任务泄漏到了下一题去跑
   - 教训：**手没停，票递了，但人没等**

2. **`asyncio.to_thread` 传了 `async def` 函数**
   - `to_thread(blocking_call, ...)` 里 `blocking_call` 是 `async def`，在线程里执行只是返回一个协程对象，**`time.sleep` 一次都没跑**
   - 症状：耗时显示"正确"（1.01 秒），但其实是**假象**——真正干活的只有那几个 `async_call`
   - 证据：`RuntimeWarning: coroutine 'blocking_call' was never awaited`
   - ⚠️ **这是我的题目设计 bug**，不是你写错。题目里 `blocking_call` 是 `async def`，但 `to_thread` 要的是普通同步函数。已修正为 `def blocking_call` + `async def bad_call` 两个版本

3. **`("1")("2")("3")("4")` —— 并列元素之间漏了逗号**
   - `("1")("2")` 在 Python 里是「用 `"2"` 去调用 `"1"`」→ `TypeError: 'str' object is not callable`
   - **这是同一类 bug 的第 3 张脸**（见下面「两大顽固 bug」）

4. **`Process` 没带 `multiprocessing.` 前缀** → `NameError`
   - 文件是 `import multiprocessing`，用的时候必须带前缀；
   - 教程注释里我一会儿写简称一会儿写全称，把你带偏了（我的锅）

5. **`for` 结尾漏冒号**（题 4a）→ `SyntaxError`，**整个文件都加载不了**，后面的错全被挡住看不见

6. **改了但没保存**（两次）
   - 说"改完了"但文件修改时间没变，跑出来还是老错误
   - 教训：**说"改完了"之前先按 Ctrl+S，再跑一次确认**

## 八、第 3 关用户提问（概念澄清）

- **`seconds=0.5` 是什么意思** → 默认参数，跟普通函数完全一样。`async def` 的参数写法和 `def` 一模一样，只是多个 `async`
- **`await asyncio.sleep(seconds)` 是什么意思** → 三层：`asyncio.sleep(s)` 只是**造**一个"睡 s 秒"的协程对象（没真睡）；`await` 把它交给事件循环并**挂起让出线程**；睡够了自己被捡回来继续
- **`r = await download_serial()` 是什么意思** → `await X` 的值**就是 X 的 `return` 值**。这也是协程最舒服的地方：线程要自己开列表收集，进程要走 Queue，协程一行 `await` 直接拿到
- **`fetch` 是什么意思** → 我造的辅助函数，不是内置的。真实 `fetch` 是 `async with session.get(url)`，练习里用 `asyncio.sleep` 替代了网络等待。这个手法叫「模拟 / 桩（mock）」
- **`return await asyncio.gather` 这个语法怎么实现的** → 两层：
  - 语法层：`await X` 是个**表达式**（会算出一个值），所以能塞进任何能放值的地方：`x = await f()` / `return await f()` / `print(await f())` / `results.append(await f())`
  - 运行时：**`await` 底层就是 `yield`**。`await X` 要求 X 有 `__await__`，拿到迭代器后不停 `next()`；没完成就抛出信号让**整个函数挂起**、控制权还给事件循环；完成了迭代器返回值就是 `await X` 的值。Python 3.5 之前协程真的是 `@asyncio.coroutine` + `yield from` 写出来的
  - 顺带解开一个疑惑：**为什么 `await` 只能写在 `async def` 里** —— 因为它底层是 yield，而 yield 只能出现在函数体里
- **"没 await 没丢进 gather，等于点了火不管了" 没懂** → 改个更准的说法：**「对着菜单点了三个菜，然后把菜单撕了，后厨根本不知道你要什么」**。`to_thread(...)` 返回的是一张票，你没 await 也没交给 gather，票就被扔了。实验 4 的 `0.00 秒` 就是铁证——真跑了不可能 0 秒
- **`target=` / `args=` 是什么意思** → 见下方「派工单」小节
- **`multiprocessing` 是什么意思** → 标准库模块（工具箱）。`import multiprocessing` 后用 `multiprocessing.Process` / `.Queue` / `.Pool` 取工具
- **`Pool(4).map(CPU任务, [N_CPU]*4)` 没懂** → 见下方

### 派工单：`Thread(...)` / `Process(...)`

```python
Thread(  target = 要跑哪个函数 ,  args = 调用它时传什么参数 )
Process( target = 改列表      ,  args = (共享列表,) )
#        ↑ 换名字，其他照搬 —— 这就是「API 完全对称」
```

- **`target=` 传函数名本身，不加括号**
  - `target=套壳` ✅（一张食谱）
  - `target=套壳("甲")` ❌（这是「现在就做菜」，会在主线程里同步跑完，**并发就没了**）
- **`args=` 必须是元组，单元素的逗号不能省**
  - `args=("甲",)` ✅ / `args=("甲")` ❌（这不是元组，就是字符串）
  - 为什么是元组：线程内部等价于 `套壳(*args)`，`*` 把元组拆开
  - ⚠️ **本题特别阴**：名字都是单字，`args="甲"` 会 `套壳(*"甲")` → `套壳("甲")` **居然蒙对了**；但换成 `"甲乙"` 就 `套壳("甲","乙")` → `TypeError`。**单字能跑、双字报错**是最难查的 bug。无脑养成 `(x,)` 的习惯

### `Pool.map`

```python
[N_CPU] * 4          # -> [5000000, 5000000, 5000000, 5000000]  列表乘 4
Pool(4)              # 雇 4 个工人待命（Process 是造 1 个干 1 件就死）
p.map(f, [1,2,3])    # 把 f(1) f(2) f(3) 分给工人【并行】算，结果收成列表
```

`map` 的语义跟内置 `map` **完全一样**，区别只是"在多个进程里并行做"。`Pool.map` 帮你做三件事：**分发 / 并行 / 收集**。

⚠️ 用 `with multiprocessing.Pool(4) as p:` 包起来，退出时自动遣散工人。

## 三、综合练习踩坑记录

**这一轮错误几乎全是「符号层面」的，概念其实都懂了：**

1. **`/` 当逗号用**（第 1、2 轮）→ `("A") / ("B")` 是字符串除法，`TypeError`
2. **`("1")("2")("3")("4")` 漏逗号**（第 3 轮，5 处）→ 变成"调用字符串"，`TypeError: 'str' object is not callable`
3. **`对象.方法 = 值`（方法赋值而非调用）** —— 3 次
   - `threads.append = threading.Thread(...)`
   - `results.append = 队列.get()`
   - `[results.append for t.await in tasks]`（第 3 关）
   - 教训：`对象.方法` 是**武器**，加 `()` 才是**开火**
4. **`for r in results:` 遍历了空列表** —— `results` 是装**输出**的，要遍历的是**输入**
5. **`asyncio.gather[...]` 用了方括号** —— 方括号是取下标，调用要圆括号
6. **`*` 放错位置** —— 要 `*[f(x) for x in ...]`，不是 `*f(x) for x in ...`
7. **`CPU任务(name)` 把字符串当参数传** —— 循环变量是 `"1"` 这种字符串，不是数字

## 四、综合练习用户提问（概念澄清）

- **`for 名字 in ("甲","乙",...)` 这个循环怎么成立的** → 最普通的 for：依次把元组每个元素赋给 `名字`。关键在**循环变量每圈都变**，所以 `args=(名字,)` 造出的 5 个线程跑的是 5 个不同名字。原来写 `for r in results` 会崩是因为 `results` 是空的
- **`args=(name,)` 里的 `name` 从哪来** → 它只在 `套壳` 肚子里存在，循环里没有。要用**自己的循环变量**
- **怎么看出 `gather(...)` 里是 3 次** → 数 `坏包装(` 出现几次。但真正的毛病是**三次括号里写的东西一模一样**（都传了整个列表），所以会拿到三个相同结果

# 第三部分：本日汇总

## 一句话总结

> **一个线程，一堆小票。开票不算干活，递进后厨才算。递完就走人，别站着等。**
>
> 补一句：**CPU 密集用进程，等 IO 用线程/协程，同步库用 `to_thread` 包一层。**

## 选择标准表（决定用哪把武器）

| 任务特征 | 选谁 | 为什么 |
|---|---|---|
| 在**等**（网络/文件/数据库） | 线程 或 协程 | GIL 挡算不挡等 |
| 在**算**（CPU 跑满） | **多进程** | 线程被 GIL 挡住，白忙 |
| 要**很多并发**（几百上千） | **协程** | 协程几 KB，线程几 MB |
| 手上是**同步库** | 协程 + `asyncio.to_thread` | 不堵事件循环 |
| 要**拿返回值** | 协程最省事 | 线程要自己收集，进程要走 Queue |
| 量**很小**（几个小文件） | **串行** | 起并发的开销比省下的还多 |
| 需要**跨进程传数据** | `Queue` | 内存隔离下唯一的门 |

**三把武器的三步走（API 完全对称）：**

| 步骤 | 线程 | 进程 | 协程 |
|---|---|---|---|
| 造 | `Thread(target=f, args=(x,))` | `Process(target=f, args=(x,))` | `f()` 得到协程对象 |
| 跑 | `t.start()` | `p.start()` | 交给事件循环（`gather`/`create_task`） |
| 等 | `t.join()` | `p.join()` | `await` |
| 拿返回值 | 自己收集 | 走 `Queue` | `await` 直接拿到 ✅ |

## 两大顽固 bug（本日重点，下次写代码前先看这条）

> **这两个都不是概念问题，是纯手感问题。概念全懂了，手还在出错。**

**① 并列元素之间漏分隔符 —— 换了三张脸**

| 轮次 | 你写的 | 实际含义 |
|---|---|---|
| 1 | `("A") / ("B") / ("C")` | 字符串除法 |
| 2 | `blocking_call(笨重1", 1.0) / (...)` | 除法 + 引号错 |
| 3 | `("1")("2")("3")("4")` | 调用字符串 |

**对策：改用 `*` 展开 + 列表推导式的写法**，逗号只在一处出现，而且元素个数肉眼可见：

```python
gather(a, b, c)                           # 要写 2 个逗号，容易漏
gather(*[f(x) for x in ("a", "b", "c")])  # 逗号只在元组里，一眼看出对不对
```

