## 二、今天顺带讲/问清楚的概念

### 1. 异常对象里装着消息

- `成绩格式错误("...")` 是**造一个对象**（跟 `Student("张三")` 一样），括号里的字被塞进对象里，存在 `.args`
- `print(e)` 打出来就是那串字；不写消息的话 `print(e)` 是**空的**（实测 `[]`，`args` 是 `()`）
- `raise` = 把这口箱子扔出去；`except ... as e` 接住的是**同一口箱子**，消息一路跟着
- **「继承 Exception」是另一件事** —— 那是给箱子贴「异常」标签，不贴标签连 raise 都不让；
  跟消息没关系。08-14 那条笔记把它俩写在一行，容易看成一件
- 一句话：**异常是一口箱子，消息是放进去的行李，继承 Exception 是箱子上的牌子**

### 2. tuple / maketrans / translate

- **tuple**：`("张三", 92)`，跟列表几乎一样，唯一区别是**建好不能改**。适合装"天生一对"的东西
- **`str.maketrans(甲, 乙)`**：造一张**对照表**，甲和乙长度必须一样，按位置一一对应。
  实测印出来是 `{65296: 48, 65297: 49, 65306: 58}` —— 是字典，键值用的是**字符编号**
- **`文本.translate(表)`**：拿表把每个字符**挨个查**，查到就换，**查不到原样留着**。
  实测：表里只放 `０１：` 三个字符，`"９２：３"` 换完是 `"９２:３"` —— `９` `３` 因为表里没有，还是全角
- 所以 `清洗` 里那两个字符串**必须凑齐十个数字**，漏一个就漏换一个

### 3. `"\n".join(行)`

讲法：**手动拼一遍 vs join 拼一遍，输出一模一样**，让他看见 join 只是省事版。

- 手动版：`行[0] + "\n" + 行[1] + "\n" + 行[2]` → 出来三行
- `"\n".join(行)` → 一模一样的三行
- **为什么胶水写在点号前面**：实测 `行.join("\n")` → `AttributeError: 'list' object has no attribute 'join'`。
  **有 join 本事的是字符串，不是列表**。主语必须是胶水
- 口诀：**谁写在点号前面，谁就是夹在中间的那个东西**
- `return` 它是因为**函数返回值只能是一个东西**，列表是"六个东西"，join 之后才变成"一块文字"

### 4. `with self.assertRaises(...) as 上下文` —— 讲了三轮才通

**第一层** —— `with self.assertRaises(ValueError):` 读作「**下面这块，我要求它报 ValueError**」。
用三个最简用例对照（`_step1_demo.py`）：

| 写法 | 结果 | 意思 |
|---|---|---|
| `int("abc")` | ok | 我要求它报，它真报了 |
| `1 + 1` | FAIL（`ValueError not raised`）| 我要求它报，它一声不吭 |
| `1 / 0` | ERROR（`ZeroDivisionError`）| 报了，但报的不是我要的那种 |

→ **报错分「报没报」和「报得对不对」两件事**

**第二层** —— `as 上下文` 跟 `except ... as e` 是同一个动作：**接住**。
用三行 print 把层次掏给他看（`_step2_demo.py`）：

```
上下文 本身是： <unittest.case._AssertRaisesContext object at 0x...>   ← 一个盒子
上下文.exception 是： invalid literal for int() with base 10: 'abc'   ← 盒子里的异常
str(上下文.exception) 是： 同上一行                                     ← 异常转成文字＝消息
```

**第三层** —— `assertIn("钱七:缺考", str(上下文.exception))` = 掏成文字，查里面有这几个字。
**为什么要查消息**：抛了错 ≠ 抛得对，可能抛的是别的错，或消息里没带原文。
正是靠这句验题面那条「异常消息里必须包含出错片段的原文」。

**总结三句**：
`with assertRaises(...)` → 你得报这个错 ／ `as 上下文` → 报了你接住 ／
`assertIn(..., str(上下文.exception))` → 报的内容里得有这几个字

### 5. 测试为什么必须写成 class

unittest **靠翻找**发现测试，规矩两条：
**找继承 `TestCase` 的类 → 跑里面名字以 `test_` 开头的方法**。不符合就跳过（这就是坑 2 的根因）。
- 继承 `TestCase` = 贴标签（跟异常继承 `Exception` 一个道理）
- 类写在文件哪里都行，unittest 自己找

### 6. 读 assertEqual 的报错（顺带教的）

```
AssertionError: '123' != '1 2 3'
- 123        ← 减号 = 程序实际拿到的
+ 1 2 3      ← 加号 = 你写进断言的
?  + +       ← 多出来的字符标在哪
```
