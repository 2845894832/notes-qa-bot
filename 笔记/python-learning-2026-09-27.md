## 二、今天的唯一新知识点：`raise ... from ...`

这个知识点**讲了三轮才通**，过程本身比结论值钱。

### 第 1 轮（失败）：写在复习速查 ⑤ 里

给了代码、给了真实输出、给了 traceback 连接语对照。**用户回："还是没听懂"。**

失败原因：一上来就讲 `__cause__` 和"异常链"这两个词，**没有回答"我为什么要费这个劲"**。他能看懂"原厂单钉在新单后面"，但看不出**这件事跟他有什么关系**。

### 第 2 轮（半通）：拆成四小步，`_raise_from_demo.py`

```
第 1 步：原厂单长什么样         → int("abc") 扔的是 ValueError
第 2 步：接住它、换自己家的单（不写 from） → __cause__ 是 None
第 3 步：同一段，只多写一个 from → __cause__ 是那个 ValueError
第 4 步：两版 traceback 的连接语不一样
```

**第 2 步那个 `None` 是关键**——它是"原厂单没了"这个事实变成看得见的东西的那一下。到这一步他问出来的是：

> `from 原始错` 的意义在？

**说明"怎么用"通了，"为什么"还没通。**

### 第 3 轮（通了）：`_why_from.py`，三版对照

同一段代码，只差 `from` 后面跟什么，三版一起跑：

| 版本 | 堆栈几张 | 连接语 | `__cause__` |
|---|---|---|---|
| ① 不写 `from` | 2 | `During handling of the above exception, another exception occurred:` | `None` |
| ② `from 原始错` | 2 | `The above exception was the direct cause of the following exception:` | `ValueError(...)` |
| ③ `from None` | **1** | （没有） | `None` |

**讲通的三个点：**

1. **① 和 ② 的"张数"都是 2** —— 说明 `from` **不是"多留了一份数据"**。不写 `from` 时 Python 也会顺手记一份（叫 `__context__`），两张单本来就在堆栈上。
   → 所以他之前那个疑问（"原厂单不是已经没了吗"）其实是**半对**：消息在 `__context__` 里，`__cause__` 里才是 `None`。
2. **`from` 改变的是那句话。** ① 读作"处理上面那个的时候又冒出别的"→ 看的人以为**两个不相干的错撞一起**；② 读作"上面那个就是下面这个的直接原因"→ 看的人知道**是一个错中途被换了说法**。
3. **③ 证明它不是装饰**：写 `from None`，堆栈真从 2 张变成 1 张，原厂单**整个不显示了**。所以 `from` 后面跟什么，**直接决定屏幕上打出什么**。

**一句大白话（最后落在这句）：**

> `except` 收下的原厂单，Python 会顺手记一笔；`from 原始错` 是你亲口说一句"这个错就是由它引起的"。

**讲法备忘（能复用的招）：**

> ⭐ **把"看不出来的东西"变成一个能数的数。**
> "两张单都在"这件事肉眼看不出来 —— 于是去数 `traceback` 里出现了几次 `Traceback (most recent call last)`，得到 `2 张` 和 `1 张`。数字一摆出来，"`from` 是有作用的"就变成事实了。
> 这跟 09-16 讲 `^` vs `\b` 时用 `enumerate` 打出**逐字位置编号表**是同一招。
> 另外，09-24 那条教训再次生效：**讲"为什么"用对照输出，不要讲设计原则。**

### 结论（写下来备查）

```python
try:
    分钟 = int(分钟文本)
except ValueError as 原始错:
    raise 格式错误(f"分钟不是整数：{分钟文本}") from 原始错
```

读法：`as 原始错` 是"接住的时候给它起个名"，`from 原始错` 是"扔新单的时候指名带上它"——**同一件事的两头，用的同一个名字**。

补充一句实话：他自己写的消息里已经把 `abc` 抄进去了，所以今天这一处 `from` 的**信息增量确实小**。它的价值在"你抄不全的时候"和"别人读堆栈的时候"。**不用觉得不写就错。**

## 三、逐块复盘

### `计费(分钟, 单价)` —— 自己写的，对着看

```python
def 计费(分钟: int, 单价: float) -> float:
    收费: float = 0
    if 分钟 <= 30:
        收费 = 0
    else:
        计费分钟 = 分钟 - 30
        计费个数 = (计费分钟 // 30)
        if 计费分钟 % 30 != 0:
            计费个数 += 1
        收费 = round(计费个数 * 单价, 2)
        if 收费 >= 40:
            收费 = 40
    return 收费
```

- ⭐ **`% 30 != 0` 这一行今天是重点：他没中招。** 复习速查 ⑧ 那张表把"写成 `>= 0` 就恒真、只在正好整半小时的行上多收一次钱"打出来了，他写的是 `!= 0`——**"写完 if 问一句条件有没有可能不成立"这条对策见效了**。
- `//` 和 `%` 都用对了，**没有把 `/` 当 `//` 用**（09-26 那个新坑没复发）。
- 封顶那处他写的是 `if 收费 >= 40`，规矩是"超过 40 按 40 收"。**这里两版结果一样**（正好 40 时设成 40 还是 40），所以不算错，没让他改。
- 第三轮补了 `round(..., 2)`（原本没保留小数）。

### `时长文字(分钟)` —— 第一版两个毛病

第一版是：
```python
if 分钟 >= 60:
    时长 = f"{时针}时{分针}分钟"
else:
    时长 = f"{分钟}分钟"
```
两个毛病：**① 要的长相是"几小时零几分钟"，不管多久都带"小时"这一截**（30 分钟要 `0小时30分钟`，所以根本不用 if 分岔）；**② `时` 少了个"小"字**。

改完：
```python
def 时长文字(分钟: int) -> str:
    return f"{分钟 // 60}小时{分钟 % 60}分钟"
```

### `解析(一条)` —— ⭐ 零提示写对，今天最硬的一块

```python
def 解析(一条: str) -> tuple[str, str, int, float]:
    段 = 一条.split(",")
    if len(段) != 4:
        raise 格式错误(f"字段应该是 4 段，实际 {len(段)} 段")
    设备编号, 手机号, 分钟文本, 单价文本 = 段

    try:
        分钟 = int(分钟文本)
    except ValueError as 原始错:
        raise 格式错误(f"分钟不是整数：{分钟文本}") from 原始错

    try:
        单价 = float(单价文本)
    except ValueError as 原始错:
        raise 格式错误(f"单价不是数字：{单价文本}") from 原始错

    if 分钟 <= 0:
        raise 格式错误(f"分钟必须是正数：{分钟}")
    if 单价 <= 0:
        raise 计费异常(f"单价必须是正数：{单价}")

    return 设备编号, 手机号, 分钟, 单价
```

**这是"上一轮说没听懂的那个坎，讲完四步当场自己写对了"。** 而且四件事一次都没漏：先数段数再解包、两个 `try/except ... as 原始错` + `from 原始错`、两个 `if` 分属两个不同的异常类、返回元组。

**特别记一句：他还用上了 `len(段)` 拼消息**（`字段应该是 4 段，实际 {len(段)} 段`）——这正是"异常消息要带出事的那个值"那条规矩的活用。

### `结算(记录)` —— 结构错，给的全文

他第一版的四个病根：

```python
    try:
      for 设备编号, 手机号, 分钟, 单价, 金额 in 记录.split(","):   # ← 记录是列表，没有 .split
          明细.append([(设备编号, 手机号, 分钟, 单价, 金额)])       # ← 多包了一层列表
          经手消息 += 1
    except 充电宝数据错误 as 单:
        失败清单.append([(str(单),repr(单))])
    else:                                                       # ← 空着，直接 IndentationError
    finally:
        return 明细,失败清单,经手消息                             # ← finally 里 return 会吞掉异常
```

四个病根：

1. `记录.split(",")` —— **记录是列表不是字符串**，`.split` 是字符串的活；列表用 `for 一条 in 记录`
2. **`try` 的位置**：他把**整个循环塞进了 `try` 里** → 第一条坏的就把整批带走了。正解是"**一条一条地循环，`try` 放在循环里面**"，这才叫"一条坏只跳一条"
3. `else` 里是**成功时才干的活**（往明细里加），不能空着
4. **`finally` 里不能 `return`**（会把异常连同返回值一起吞掉），它只负责数数，`return` 放函数最后一行

改完的正确版：
```python
    for 一条 in 记录:
        try:
            设备编号, 手机号, 分钟, 单价 = 解析(一条)
        except 充电宝数据错误 as 错:
            失败清单.append((一条, str(错)))
        else:
            明细.append((设备编号, 手机号, 分钟, 单价, 计费(分钟, 单价)))
        finally:
            经手 = 经手 + 1

    return 明细, 失败清单, 经手
```

值得记的：`except 充电宝数据错误 as 错` + `str(错)` 装进失败清单，**提示一次就写对了**。

### `汇总(明细)` —— 类型不配套，第 2 次

    总结: dict[str, float] = []       # ← 注解是 dict，给的是 []

### 卡住的点：`" ".join(sys.argv[1:])` "不知道怎么拼好的"

**根因不在 join，在他拿了一颗珠子去试它。**

```
sys.argv = ["...", "闭包是什么"]      ← 切完只剩 1 颗
" ".join([...]) = 「闭包是什么」
"".join([...])  = 「闭包是什么」       ← 三种一模一样
"-".join([...]) = 「闭包是什么」
```

**一颗珠子，绳子无处可塞** —— 所以看着像 join 什么也没干。

换成两颗（`python _join_sys_argv_demo.py 闭包 是什么`）：

```
" ".join(['闭包', '是什么'])  = 「闭包 是什么」
"".join(['闭包', '是什么'])    = 「闭包是什么」
"-".join(['闭包', '是什么'])   = 「闭包-是什么」      ← 绳子显形
```

**又是"把看不出来的东西变成能数的数"这一招（跟数 traceback 张数同源）：珠子 1 颗看不出来，给 2 颗一眼就懂。**
