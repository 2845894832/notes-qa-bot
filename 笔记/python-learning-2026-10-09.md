## 一、SQL 第 3 关「改和删」

**材料**：速查 `SQL第3关-速查.md`（8 节）+ 演示 `_sql_第3关_演示.py` + 练习 `sql_practice_第3关.py`
（答案 `_答案暂存\sql_practice_第3关_答案.py`）

**学的东西**：`UPDATE ... SET 列 = 值 WHERE ...` / `DELETE FROM ... WHERE ...` /
`PRIMARY KEY` 是行的**身份证** / `游标.rowcount`。

**验收**：6 题全过 —— `动 1 / 2 / 1 / 1 / 3 行`，最后剩 5 行（编号 4/5/6/7/9）。

**⭐ 本关的核心，用一个数讲通的**：

```
UPDATE 收支 SET 金额 = 30 WHERE 编号 = 3     → 游标.rowcount = 1
UPDATE 收支 SET 金额 = 0                     → 游标.rowcount = 8
```

`rowcount` **只数"动了几行"，说不出"动的是哪几行"**。
第 3 关第一个大坑就在这儿：**他删错了行**（该删编号 8，写成了编号 3），
`动 1 行` 照样打出来，一点异常都没有 —— 是最后那句"还剩几行、编号是哪几个"才把它揪出来。

> **一句话**：`rowcount` 是**收据上的数字**，不是**收据上的明细**。
> 删/改完必须再 `SELECT` 一遍看**剩下的是谁**。

**踩的坑**：

1. `INESRT` 拼错 + 漏 `VALUES` + 漏单引号（`INSERT` 这块速查里没写，他问了一句，
   我把 `SQL第1关-速查.md` 第 ② 节补上了交叉引用）。
2. 删错行（上面那条）。
3. 老毛病：说了"改完了"但那行没动。

## 二、SQL 第 4 关「聚合与 JOIN」

**材料**：速查 `SQL第4关-速查.md` + 演示 `_sql_第4关_演示.py` + 练习 `sql_practice_第4关.py`

**学的东西**：
- 聚合：`COUNT(*)` / `SUM(列)` / `AVG` / `MAX` / `MIN`
- `GROUP BY` 分组、`ORDER BY SUM(...) DESC` 排序
- **第二张表** `分类`（分类号 / 分类名）
- `JOIN ... ON 收支.分类号 = 分类.分类号`

**为什么要第二张表**（这一关的"为什么"）：`收支` 里只写了个**分类号**，
光看号不知道是"吃饭"还是"交通"。名字单独放一张表，
**用时靠号连起来** —— 这就是"数据库是文件柜"那个类比里，
**两个抽屉靠一张索引卡对上**。

**验收**：6 题全过 —— `8 / 162.0 / 74.0 / 6 行 / 8 行 / 3 行`。

**踩的坑**：

1. **并列漏逗号**：`SELECT 项目 SUM(金额)` → 少个逗号（老毛病再犯）。
2. 🆕 **中文顿号 `、` 混进 SQL**：`收支.项目、收支.金额` ——
   跟第 1 关"中文注释抄进 SQL"**同一家族**。**不只是中文字进不来，中文标点也进不来。**
   ⚠️ 以后记住：**SQL 里所有标点都得是英文半角**。
3. 🆕 **表名前缀加到了函数上**：`收支.SUM(金额)` → `near "(": syntax error`。
   正解是 `SUM(收支.金额)` —— **`表名.` 只能加在列名上，不能加在函数上**。
4. `GROUP BY` 的查询里 `SELECT` 列写多 —— 规矩是
   **`SELECT` 的列要么在 `GROUP BY` 里、要么被聚合函数包着**。

**⭐ 亮点**：第 5 题的 JOIN `ON 收支.分类号 = 分类.分类号` 加三处表名前缀，
**本关最难的一个，一次写对，零返工**。

## 四、C1 项目 · 第 ③ 步「Pydantic 门卫」

**方案** `C1-FastAPI小服务-方案与进度.md` ｜ **速查** `Pydantic-复习速查.md`（6 节）｜
**讲解** `FastAPI小服务\讲解.md` 第 3 步 ｜ **演示** `_pydantic_review_demo.py`

### 为什么要加门卫（用能数的数讲）

在 `/docs` 里试"不填"和"填个空的"，**是两回事**：

| 怎么发 | 状态码 | 结果 |
|---|---|---|
| 打 `/问`（**这栏不填**） | **422** | `Field required`，连函数都没进 |
| `/问?问题=`（**填了，是空的**） | **200** | 照收，还**真去问了一次模型** |

**一句话：FastAPI 白送的那层，只查「这栏填没填」，不查「填的东西算不算数」。**

### 他写的（最终版）

```python
class 提问(BaseModel):
    问题 : str = Field(min_length=1, max_length=200)

@app.post("/问")
def 问(单子: 提问) -> dict:
    答案 = 主程序.回答一个问题(单子.问题, 块们)
    return {"答案": 答案}
```

### 验收（我起服务发 5 个请求，已核）

```
{"问题": ""}          422  string_too_short
{"问题": "x"*300}     422  string_too_long
{}                    422  missing
{"问题": 123}         422  string_type
{"问题": "闭包是什么"}  200  {"答案":"笔记里没有。"}
```

**⭐ 能数的数**：终端上 `===== 问：` 那行**只出现 1 次**，
而单子递了 5 张 —— **那 4 张不合格的，函数一次都没被调用**。
「根本进不到函数」这句抽象的话，量出来就是"**1 次**"。

> ⚠️ 跟轮次 9 的日志题对比着看：
> **日志题是"坏行也进函数，进去之后记一笔 warning 跳过"；
> 这次是"根本进不来"**。两件事长得像，位置完全不同。

### 踩的坑（第 1 轮 3 处，第 2 轮一次全改对）

1. **试错代码写在了最外层**（`问("问题": "")` ×3 行）—— 语法错，
   **整个文件加载不了，后面两处错全被它挡住**。
   （⚠️ 每日题台账里 09-27 也栽在同一个地方 —— **这是第 3 次**。）
   → **想试错误 → 写进测试；模块级只放声明，不放会跑的代码。**
2. `-> str/BaseModel:` —— 中间那个**斜杠被 Python 当成除法**去算，两个类型除起来直接报错。
3. `单子.提问` → 应为 `单子.问题`（`提问` 是**类名**，单子上那一栏叫 `问题`）。

**另一个变化**：改成 `POST` 之后**地址栏测不了了**（地址栏只会发 GET），
必须走 `/docs` 里的 `Try it out`。他第 ② 步是靠地址栏测的，这一步撞上了这个变化。
